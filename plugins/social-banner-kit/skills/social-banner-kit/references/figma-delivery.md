# Редактируемая выдача Figma — только по запросу

Включать этот режим только при явном запросе Figma. Обычный заказ баннеров завершается PNG/JPEG; не предлагать обязательный переход в Figma и не подключать её для каждого задания. Согласование направления и профессиональный контроль качества сохранять в обоих режимах.

## До сборки

1. Прочитать доступные актуальные навыки Figma: `figma-use` перед работой с Plugin API, `figma-create-new-file` перед созданием файла; другие навыки — по их области применения. Использовать штатные инструменты и текущие схемы. Для статичных баннеров не навязывать процесс проектирования веб-интерфейса или готовый UI kit.
2. Если пользователь дал целевой файл/страницу, проверить доступ и работать там. При отсутствии файла создать новый в подключённом аккаунте по правилам Figma; выбор рабочей области уточнять только когда он действительно требуется. Не менять права доступа или публиковать файл без отдельного запроса. При недоступной интеграции назвать конкретное ограничение и продолжать независимую подготовку; не заменять требуемый макет плоской картинкой под видом выполненной задачи.
3. Проверить фактическую доступность фирменных семейств и начертаний в Figma. Наличие файла шрифта локально не доказывает его доступность в Figma. Загрузить доступные шрифты штатным способом до записи текста; при недоступном шрифте получить нужный доступ/исходник или согласовать замену. Не подменять гарнитуру молча и не переводить обязательный текст в кривые ради обхода проблемы. Сохранить локальные подтверждённые font-файлы для существующего технического контроля экспортов; если их нельзя получить, явно назвать ограничение этого контроля и не заявлять о полном `PASS`.
4. Сначала спланировать слои и пересечения сцены. Подготовить людей, товары, фон и передний план отдельными растровыми ассетами там, где их самостоятельная правка имеет смысл. Сохранить сложный контактный свет/ретушь в фотогруппе, если разбор разрушит сцену; границы такой редактируемости обозначить при согласовании направления. Не обещать восстановить исходные слои из одного готового JPEG.

## Структура макета

- Создать отдельный финальный фрейм на каждую запрошенную площадку каждого комплекта с точными размерами из профиля. Именовать понятно: `concept-01 / VK`, `concept-01 / RUTUBE`, `concept-01 / YouTube`. Варианты согласования и старые редакции не смешивать с финальными фреймами.
- Набранные заголовки, подписи, домен и контакты сделать настоящими редактируемыми текстовыми слоями. Сохранить точный текст, начертания, переносы, размеры, интервалы и выравнивание. Не растрировать их и не маскировать имитацией редактируемости поверх полного изображения баннера.
- Логотип и графику из оригинального SVG импортировать вектором. Растровый оригинал сохранять растровым; не трассировать его автоматически и не перерисовывать ради формальной векторности.
- Фон, паттерн, графику, логотип, фотогруппы и текст разнести по именованным слоям/группам. Использовать маски, прозрачность и эффекты там, где они сохраняют нужный вид. Простую графику и доступный векторный паттерн держать редактируемыми; сложные фактуры и фотографию оставлять качественным растром. Надписи на фотографии упаковки не выдавать за отдельные текстовые слои.
- Повторяемые блоки собирать переиспользуемыми элементами, когда это помогает правкам. Не упрощать рекламную композицию ради шаблона, авторасстановки или требования сделать каждый пиксель векторным. Сохранять пропорции и качество импортированных ассетов.
- Безопасные области показывать направляющими либо отдельной скрываемой группой. Убрать её из финального экспорта. Реальные маски фотографий и запланированное кадрирование сохранять в финальной композиции.

## Проверка и выдача

1. Прочитать обратно структуру каждого финального фрейма: имена/ID, типы слоёв, текст, реальные семейства/начертания, размеры и границы объектов. Убедиться, что все обязательные надписи представлены текстовыми слоями, а изображения загружены и не пусты. Наличие пары текстовых слоёв поверх цельной растровой обложки не доказывает редактируемость макета.
2. Сравнить вид фреймов с утверждённым направлением; проверить реальные переносы, маски, порядок слоёв, свет/контактные тени и качество фотографий. При визуальном дефекте исправлять затронутые слои, сохраняя удачные части.
3. Экспортировать из этих же финальных фреймов в размере 1:1. Проверить готовые файлы по обычной методике: масштаб реального показа, интерфейсные маски, 100%, фактические размеры/формат/вес и manifest. Не выдавать отдельную внешнюю сборку, отличающуюся от макета Figma. Не скрывать непрошедший технический контроль шрифтов; при отсутствии необходимого исходника сохранить рабочую версию и назвать недостающий материал.
4. По умолчанию вернуть проверенную ссылку на Figma и заказанные PNG/JPEG. При явном «только Figma» вернуть только ссылку; экспорты всё равно сделать для внутренней проверки. Не создавать дополнительные пользовательские форматы или распространять файл на всех по ссылке без запроса.
5. Для последующих правок сохранять file key, ID фреймов, исходные ассеты и предыдущую мастер-версию в паспорте. Редактировать существующие слои и экспортировать обновлённые фреймы; не заменять весь макет новой плоской генерацией.
