# Матрица проверки

Статус каждой проверки: `passed`, `failed`, `candidate`, `not_checked`, `blocked`, `approved_exception`. Каждая ошибка требует наблюдения, ожидаемого поведения, причины/гипотезы и действия. Размеры/цвета без эталона не являются ошибкой сами по себе.

| Область | Обязательные проверки |
|---|---|
| Дизайн-код | Роли цвета, контраст, шрифты/начертания и фактическая загрузка; сетка/контейнеры, отступы, радиусы, иконки; согласованность между шаблонами |
| Кнопки | ≤3 основных варианта; назначение, реальный результат действия, hover и контраст, focus/active/disabled/loading; подпись и доступное имя; кнопки тизеров, ссылки на карточках |
| Текст | ≤3 стиля основного параграфа; шрифт, размер, line-height; иерархия h1–h4; ровно 1 h1 в DOM; переносы, длинные названия, не обрезан/не перекрыт |
| Вёрстка | Все viewport; горизонтальный overflow, случайные пустоты, пустые блоки, наезды на изображения, footer, sticky/fixed, слои модалок, 2550 px; обрезка важных объектов |
| Контент | Орфография/пунктуация, словарь бренда/терминов; адреса/телефоны/время, одинаковые подписи; placeholder, Lorem Ipsum, тестовые тексты, недостоверные утверждения только при наличии доказательства |
| Ссылки | Raw href/src/srcset/action/poster/data-src/data-srcset; relative-only внутренние HTML URL; target/rel для внешних; HTTP ошибки и soft 404; неправильное назначение/пустая страница; корректные anchors; href="#" проверять поведением |
| Метаданные | title и description уникальны/релевантны; charset, viewport; canonical, robots/индексация по назначению; OpenGraph/Twitter по требованиям; favicon; JSON-LD по типу страницы без выдуманных рейтингов |
| Формы | Ввод/удаление/вставка, маски, числовые поля/границы, selects, textarea, autocomplete, длинные значения, focus/blur; labels/required; значения, placeholder, ошибки и фокус контрастны; без отправки |
| Доступность | Клавиатура/порядок фокуса, имя кнопки, labels, ловушка/возврат фокуса в модальном окне, скрытый контент не в таб-порядке; zoom/reflow; reduced-motion; alt и touch-target |

| Изображения | См. images.md: ≤300 000 bytes, размеры/форматы/резкость, названия/alt, crops, содержание, локальные повторы, внешняя уникальность с доказательствами |
| Скорость | Navigation timing, TTFB, resources, LCP/CLS при наличии измерителя, длинные задачи; большой JS/CSS/шрифты, lazy-loading/preload; 3 сравнимых прогона подозрительных результатов |
| CMS/код | Пользовательские/системные стили различать; ручные inline-стили отдельно от runtime; CSS/JS конфликты; семантика HTML; исходники/сервер не считать проверенными без доступа |

## Контраст полей

Ориентир WCAG AA: текст и placeholder ≥4.5:1; крупный текст ≥3:1 (18 pt/24 CSS px или 14 pt/~18.67 CSS px bold). Элементы управления и видимый индикатор состояния обычно ≥3:1. Это пороги доступности, а не произвольная палитра.

Проверять значение/placeholder/label/error, placeholder opacity, -webkit-text-fill-color, autofill и focus. Учитывать прозрачность, фон предков, фото/градиент, disabled исключения. Автоматический расчёт на неоднозначном фоне — candidate или not_checked, а не гарантированное соответствие. Светлая рамка сама по себе не ошибка, если поле различимо иными достаточными способами.

## Абсолютные URL и исключения

Внутренние HTML адреса с доменом запрещены правилом проекта. Проверять **raw-атрибут**, т.к. свойство DOM.href всегда может выглядеть абсолютным. `//domain` тоже содержит домен. `<base>` проверять отдельно. В srcset разбирать кандидаты, а не делить data URL произвольно по запятым.

Внешние карты/соцсети/отзывы, CDN, vendor scripts — реальные внешние назначения: показывать необходимость исключения или локализации, не предлагать `/yandex.ru/...`. `tel:`/`mailto:` не веб-адреса с доменом; считать допустимыми функциональными протоколами и фиксировать корректность назначения. data/blob — служебные источники, проверить контекст, не заменять механически.

Canonical, og:url/og:image и URL в JSON-LD оценивать отдельно: некоторые форматы/потребители требуют абсолютные URL. Не превращать требование пользователя в поломку SEO; спорный конфликт отметить «нужно решение по исключению», сохранив корректную рекомендацию. Не распространять правило HTML автоматически на все CSS url()/API endpoints без уточнения области.

## Доказательства и исполнители

Обязательные поля findings.json: id, priority (P1/P2/P3), owner (user/codex), status (candidate/confirmed/rejected), category, message, recommendation, occurrences [url, viewport, selector, resourceUrl, evidence], cmsOrigin, cmsConstraint, verification. `resourceUrl` обязательно указывай для находки о конкретном файле (например, тяжёлом изображении). `url` каждой страницы остаётся полным URL. Файлы/строки добавлять только если они реально получены с сайта и проверены.

Файл `checklist.md` выдавай с тремя разделами в фиксированном порядке: 1) визуальные ошибки и дизайн; 2) вёрстка, стили и орфография; 3) глобальные проблемы. Внутри сортируй по P1 → P2 → P3. Каждый пункт — отдельный Markdown-чекбокс с исполнителем и кликабельным URL страницы; находки по ресурсу включают прямую ссылку на URL файла. Для отсутствующего meta description перечисляй все затронутые URL, а не только количество или общее описание.

P1: блок основного чтения/действия, серьёзная поломка навигации/адаптива. P2: заметная ошибка оформления/контента/доступности/скорости. P3: небольшая ошибка, техническая гигиена, рекомендация. Субъективное улучшение помечать рекомендацией. Protected CMS не снижает приоритет поломки.

manifest/coverage хранит discovered, included, sampled, excluded (с причиной), HTTP, widths, engines и статусы `capture`, `visual`, `interaction`, `content`, `image_semantics`. `capture=passed` не заполняет остальные автоматически. Недоступность Safari не заменять результатом WebKit.
